1.2 代码 / 智能体类：从"会做题"到"能干活"

HumanEval(+) / MBPP

给定函数签名写实现，跑单元测试。pass@1 是单次通过率，pass@k 是采样 k 次至少一次通过。+ 版本补充大量隐藏测试，专门压"假通过"。

LiveCodeBench

题目按时间滚动更新，只评测模型训练截止之后的题，直接对抗训练集污染。

SWE-bench (Verified)

给一个真实 GitHub issue 与仓库，要求端到端修好 bug，用官方测试验证。指标是解决率 %，测的是"能不能干活"。

GAIA

真实世界多步任务（检索 + 推理 + 工具调用），按 L1–L3 难度分层报成功率。

一个例外：HELM

HELM 不追求合成一个总分，而是分维度出报告——准确率、校准（calibration）、鲁棒性、公平性、效率并列。它是极少数把"校准"列为正式评估维度的框架，这一点对 Part 2 很关键。

对 Part 3 的伏笔
这类评测天然产出多级信号：测试通过 3/5 个用例、五步推理走对三步。二值化会把它压成 0/1，白白丢掉精度——这正是 GRM/GPCM 的用武之地。

1.3 主观偏好类：没有标准答案时怎么排名

Benchmark机制输出
MT-Bench80 组多轮对话，用强模型（如 GPT-4）当裁判，逐轮打 0–10 分平均分

Arena 的排名机制值得单独说

它用 Bradley–Terry 模型（象棋 ELO 的推广）从海量成对比较中估计每个模型的潜在强度 βi\beta_iβi​：

P(i≻j)  =  eβieβi+eβj  =  σ(βi−βj)P(i \succ j) \;=\; \frac{e^{\beta_i}}{e^{\beta_i}+e^{\beta_j}} \;=\; \sigma(\beta_i-\beta_j)P(i≻j)=eβi​+eβj​eβi​​=σ(βi​−βj​)
  • 匿名防品牌偏置；主动采样优先挑选"最不确定的一对"来比，提高信息效率；
  • 给出置信区间：对战场次少的模型区间宽，明确告诉你"这个排名还不确定"。
但它仍然没有校准维度
Arena 回答的是"人更喜欢谁"，不是"模型自己认为对不对、以及这个判断值不值得信"。

PART 2

让模型自己给出置信度

2.1 什么是口头置信（verbalized confidence）

在给出答案的同时，要求模型输出一个数值或等级来表达"我对这个答案有多大把握"，例如 {"answer":"3","confidence":0.62}。它不需要访问 logits，因此是黑盒 API 唯一普适的置信度通道。

2.2 "置信度可信"在数学上是什么意思

校准（calibration）的定义非常朴素——当模型说 q 时，长期看确实有 q 的比例答对：

P(y=1  ∣  p^=q)  =  q,∀q∈[0,1]\mathbb{P}\big(y=1 \;\big|\; \hat{p}=q\big) \;=\; q, \qquad \forall q\in[0,1]P(y=1​p^​=q)=q,∀q∈[0,1]

注意它和"判别力"是两件事。判别力关心排序对不对（给更可能的题更高分），校准关心数值本身准不准。一个模型可以排序很准但严重过度自信。

先给结论
口头置信用于排序 / 判别通常可靠；用于当成真实概率则普遍过度自信，必须先验证、必要时做事后校准（温度缩放 / Platt / 等渗回归）。

2.3 关键论文：Lin et al. 2022《Teaching Models to Express Their Uncertainty in Words》

arXiv:2205.14334 · GPT-3 davinci 175B · 自建数据集 CalibratedMath

它比较的"三种概率"

类型怎么得到 P(答案正确)是否需训练特点
Answer logit模型自己答案 token 的归一化 logprob不需要只衡量某一个具体字符串；一题多解时系统性低估
Indirect logit答案后追加 True/False:，读 True 的 logprob，即 P(True∣Q,A)P(\text{True}\mid Q,A)P(True∣Q,A)需微调能给模型自己的开放答案打分
Verbalized直接输出 "19%" 或等级词需微调有自然语言的表达力，可表达连续分布
出发点：校准的是"模型自己的"不确定性
GPT-3 在计算机安全问答上胜过多数人类，却在 23×723\times 723×7 这类算术上远不如人。所以不能照抄人类的置信表达。

2.4 闭源模型下，具体怎么问

方案 A：只要所选答案的置信度
请回答问题，并说明你对该答案
正确的把握程度。严格以 JSON 返回：
{"answer": "...", "confidence": 0.xx}

问题：<问题>　选项：<选项>
方案 B：要整个选项分布（推荐）
这是多选题。请给出每个选项为正确
答案的概率，概率之和必须等于 1。
严格以 JSON 返回：
{"A":0.xx,"B":0.xx,"C":0.xx,"D":0.xx}

问题：<问题>

三条纪律

  1. 要分布，不要单个把握：拿到完整分布才能算 NLL / Brier / ECE；模型不提示时不会自动归一，必要时后处理归一。
  2. 答案与置信分离：先独立作答再要置信度（或分字段给出），避免相互污染。
  3. 结构化输出：强制 JSON，避免得到"看起来很像"但无法量化的文字。
优先级
有 logprob → 用 logprob ＞ 口头置信 ≈ 采样一致性。采样一致性（温度 > 0 采样 K 次，取最高频答案占比）不受"模型自我标高"影响，是很好的交叉验证信号。
PART 3

IRT 评价被二值困住了吗？GRM / PCM 能补什么

3.1 先回顾：二值 IRT 在做什么

项目反应理论把"模型答题"类比为"考生答卷"：同时估计模型能力 θi\theta_iθi​ 与题目参数（难度 bjb_jbj​、区分度 aja_jaj​、猜测 cjc_jcj​），而不是简单数答对了几题。

1PL (Rasch):P(yij=1∣θi)=eθi−bj1+eθi−bj\text{1PL (Rasch):}\quad P(y_{ij}=1\mid\theta_i)=\frac{e^{\theta_i-b_j}}{1+e^{\theta_i-b_j}}1PL (Rasch):P(yij​=1∣θi​)=1+eθi​−bj​eθi​−bj​​
2PL:P(yij=1∣θi)=11+e−aj(θi−bj)\text{2PL:}\quad P(y_{ij}=1\mid\theta_i)=\frac{1}{1+e^{-a_j(\theta_i-b_j)}}2PL:P(yij​=1∣θi​)=1+e−aj​(θi​−bj​)1​
3PL:P(yij=1∣θi)=cj+(1−cj)11+e−aj(θi−bj)\text{3PL:}\quad P(y_{ij}=1\mid\theta_i)=c_j+(1-c_j)\frac{1}{1+e^{-a_j(\theta_i-b_j)}}3PL:P(yij​=1∣θi​)=cj​+(1−cj​)1+e−aj​(θi​−bj​)1​

3PL 的 cjc_jcj​ 正是为多选题的"蒙对"设计的——这是二值框架内处理猜测的标准做法。

3.3 二值化到底丢了什么

场景实际存在的多级信息二值化后的损失
数学 / 推理五步推导走对三步；中间步骤部分正确"差一点做对"与"完全不会"被判为同一类
代码生成5 个单元测试过了 3 个丢失通过比例，能力估计方差变大
开放问答 / rubric评分细则里命中 2/4 条只保留"全命中"才算对
多选题干扰项质量不同（选了"接近正确"的 vs 选了显然荒谬的）所有错误选项等权
模型自评置信度模型给出的 0.62argmax 之后只剩 0/1
后果
信息量下降 → 能力估计的标准误变大 → 榜单上"谁更强"的判定更依赖题量；同时头部模型在简单题上全部答对，产生天花板效应，区分度归零。

3.4 GRM：Samejima 等级反应模型

把作答结果从 \{0,1\} 扩展到有序类别 k=0,1,…,mjk=0,1,\dots,m_jk=0,1,…,mj​（如 0=完全错、1=部分对、2=基本对、3=完全对）。核心技巧是对累积概率建模：

Pjk∗(θ)  =  P(X≥k∣θ)  =  11+e−aj(θ−bjk),k=1,…,mjP^{*}_{jk}(\theta)\;=\;P(X\ge k\mid\theta)\;=\;\frac{1}{1+e^{-a_j(\theta-b_{jk})}},\qquad k=1,\dots,m_jPjk∗​(θ)=P(X≥k∣θ)=1+e−aj​(θ−bjk​)1​,k=1,…,mj​
P(X=k∣θ)  =  Pjk∗(θ)  −  Pj,k+1∗(θ),Pj0∗=1,  Pj,mj+1∗=0P(X=k\mid\theta)\;=\;P^{*}_{jk}(\theta)\;-\;P^{*}_{j,k+1}(\theta),\qquad P^{*}_{j0}=1,\ \ P^{*}_{j,m_j+1}=0P(X=k∣θ)=Pjk∗​(θ)−Pj,k+1∗​(θ),Pj0∗​=1,  Pj,mj​+1∗​=0
  • bjkb_{jk}bjk​ 是"类别阈值"：跨过第 k 个台阶所需的能力水平，通常要求 bj1<bj2<⋯<bjmjb_{j1}<b_{j2}<\dots<b_{jm_j}bj1​<bj2​<⋯<bjmj​​；
  • aja_jaj​ 仍是区分度：整道题共用一个斜率；
  • 直观理解：把一道题变成一叠递进的台阶，能力越高，越可能站上更高的台阶。
这一步就是你说的"阶梯"
GRM 正是把 0/1 的"一级台阶"换成 mjm_jmj​ 级台阶，用阈值参数刻画每一级。

3.5 PCM 与 GPCM：分部评分模型

PCM（Masters，Rasch 系，无区分度参数）

P(X=k∣θ)  =  exp⁡ ⁣[∑h=0k(θ−δjh)]∑r=0mjexp⁡ ⁣[∑h=0r(θ−δjh)]P(X=k\mid\theta)\;=\;\frac{\exp\!\big[\sum_{h=0}^{k}(\theta-\delta_{jh})\big]}{\sum_{r=0}^{m_j}\exp\!\big[\sum_{h=0}^{r}(\theta-\delta_{jh})\big]}P(X=k∣θ)=∑r=0mj​​exp[∑h=0r​(θ−δjh​)]exp[∑h=0k​(θ−δjh​)]​

GPCM（Muraki 广义分部评分，带区分度）

P(X=k∣θ)  =  exp⁡ ⁣[∑h=0kaj(θ−bjh)]∑r=0mjexp⁡ ⁣[∑h=0raj(θ−bjh)]P(X=k\mid\theta)\;=\;\frac{\exp\!\big[\sum_{h=0}^{k}a_j(\theta-b_{jh})\big]}{\sum_{r=0}^{m_j}\exp\!\big[\sum_{h=0}^{r}a_j(\theta-b_{jh})\big]}P(X=k∣θ)=∑r=0mj​​exp[∑h=0r​aj​(θ−bjh​)]exp[∑h=0k​aj​(θ−bjh​)]​
  • PCM / GPCM 建模的是相邻类别的难易对比（从 k−1 跨到 k 的这一步有多难），而 GRM 建模的是累积概率；
  • GPCM 的项目信息可写成 Ij(θ)=aj2[E[k2∣θ]−(E[k∣θ])2]I_j(\theta)=a_j^2\big[\mathbb{E}[k^2\mid\theta]-(\mathbb{E}[k\mid\theta])^2\big]Ij​(θ)=aj2​[E[k2∣θ]−(E[k∣θ])2]，即类别得分的条件方差；
  • 当 mj=1m_j=1mj​=1 时，GPCM 退化为 2PL，PCM 退化为 1PL —— 说明它们是二值模型的严格推广。

3.6 GRM / GPCM 怎么选

模型建模对象参数适用
GRM累积概率 P(X≥k)P(X\ge k)P(X≥k)，阈值 bjkb_{jk}bjk​ 递增aj,bj1..ma_j, b_{j1..m}aj​,bj1..m​Likert 量表、rubric 等级、"完全不会→全对"的整体等级

PART 4

Jev 模型，以及它对不确定性量化的启示

4.1 Jev 是什么

TypeSafe AI 提出的 System One（系统一）决策模型。它不生成自由文本，而是：开发者预先声明问题与答案空间，模型只从这些选项里选，并给出每个选项的校准概率。

  • 非自回归：一次性并行求值所有已声明的问题，而不是逐 token 生成；
  • RLCD（Reinforcement Learning for Calibrated Decisions）：把"校准"直接写进训练目标；
  • 定位：高频、有界、低延迟的决策即服务，而不是通用对话模型。
三种决策类型
Choice（多选一，如 紧急/普通/低优先级）· Score（在定义标尺上打分 0–100）· Yes/No 概率（这句话为真的概率，如"这是账单问题？"→ 0.81）

4.2 底层原理：softmax 之外，关键在训练目标

① 推理时：一次 softmax 得到条件分布

P(答案k∣x)  =  ezk∑jezjP(\text{答案}_k\mid x)\;=\;\frac{e^{z_k}}{\sum_{j}e^{z_j}}P(答案k​∣x)=∑j​ezj​ezk​​

softmax 只负责"把分数变成概率"，它不保证概率准。

② 第一段训练：学会判断

L  =  −log⁡P(y∗∣x)\mathcal{L}\;=\;-\log P(y^{*}\mid x)L=−logP(y∗∣x)

最小化交叉熵，让条件分布"大体正确"——但这只保证通常能选对，不保证数值可信。

③ 第二段 RLCD：用恰当评分规则当奖励

r=log⁡P(y∗∣x)或r=−∑k(pk−1{k=y∗})2r=\log P(y^{*}\mid x)\quad\text{或}\quad r=-\sum_{k}\big(p_k-\mathbf{1}\{k=y^{*}\}\big)^2r=logP(y∗∣x)或r=−k∑​(pk​−1{k=y∗})2
为什么这能校准：这是数学保证，不是技巧
恰当评分规则的性质是——只有当输出等于真实条件概率时，期望评分才最优。把 0.6 虚报成 0.9，一旦猜错惩罚极重，期望上得不偿失。于是策略梯度会一路把输出分布"拽"向真实分布：校准是被奖励结构逼出来的，不是事后打补丁。

架构非自回归，单次并行前向自回归逐 token 预测
速度 / 成本约 70–500ms；输出近乎不计成本随长度与难度显著上升
置信度原生输出校准概率需单独设计或估计
集成类型化结果直接进程序逻辑需 schema、校验、护栏
它的硬边界
不会写作、不会对话、不做慢思考推理；答案空间必须预先枚举，无法处理未知结果的问题；模糊或高风险情况仍需 LLM / 人工兜底。

4.4 实际架构：级联（Cascade），而非二选一

Jev 高频有界决策层  ── 置信度高 ──▶  直接执行
        │
        └─ 置信度低 / 模糊 ──▶  升级给大模型  ──▶  仍不确定 ──▶  人工

典型例子 · PII 预检：客户请求先经 Jev 分类为「可发送 / 需匿名化 / 不确定」，只有"可发送"才真正调用昂贵的云端 LLM——既控风险又省钱。这避免了"一个大模型包办全流程"带来的高成本与高延迟。

一个诚实的判断
从数学本质看，Jev 就是一个分类器，和逻辑回归、softmax 分类器没有范式级区别。真正的新东西在工程定位、训练目标与产品形态：把"校准"从后处理步骤提升为训练的直接优化目标，并做成高频低延迟的服务。

4.5 对不确定性量化的五条启示

  1. 约束输出空间，不确定性才有意义。Jev 之所以能给出可靠的 0.77，是因为答案被锁死在有限集合里。这印证了语义熵 / 自我一致性路线的合理性——做 UQ 时先把开放题改写成有界选择。
  2. 校准应进入训练目标，而不是事后补丁。多数 LLM UQ 是温度缩放、Platt、分箱等后处理；RLCD 证明可以端到端优化。可做方向：用 −Brier-\text{Brier}−Brier 或对数评分作奖励做偏好优化（类似 DPO/RLHF，但奖励换成"概率是否诚实"）。
它够不到、正是你主场的三件事
发散性 / 语义不确定性（没有预定义答案空间）· 长链推理中的置信传播（过程级 UQ）· 幻觉与事实性不确定（自信地胡说）。

4.6 一个可落地的研究设计

"约束空间 + 校准奖励"组合拳
  1. 对同一批题，先用提示把开放题改写成有界选择，让闭源模型直接吐出选项概率分布；
  2. 同时采集 口头置信 与 采样一致性 两个代理信号；
  3. 若具备微调条件，用恰当评分规则（对数评分 / Brier）作为目标做一轮校准微调；
  4. 在同分布与跨分布漂移两种条件下，比较三种信号的 Brier 与 ECE；
  5. 再用二值 3PL 与多级 GPCM 分别估一次能力 θ\thetaθ，看评分粒度对排名的影响。

这个设计一次性产出三张有价值的对比表：① 哪个代理信号最可信；② 只看准确率会错误排名哪些模型；③ 多级评分比二值评分多多少信息。它们正好是主流榜单普遍缺失的三栏。

造标签的最小套路（只要 0/1 正确性即可）
模型 zero-shot 作答 → 按题型/科目分桶 → 用该桶的经验准确率当标签 → 微调或用 few-shot（随机 k-shot + EV 解码）让其输出校准置信。

总结

部分现有做法可改进之处
Benchmarkaccuracy / pass@k / ELO 排名饱和与污染；缺校准维度；差距常不过显著性检验
自评置信度口头置信 + 事后校准把校准写进训练目标；验证必须区分判别力与校准

Jev受限空间 + RLCD启示：约束空间、校准入训练目标、不确定度当路由器
一句话主线
现有评测把"模型有多确定"的信息丢在了三个地方：打分时被二值化、排名时被准确率取代、报告时被省略。把这三层分别补回来 —— 用多级评分（GRM/GPCM）、用恰当评分规则（Brier/NLL）排名、并在报告里固定加上校准与不确定度两栏。
